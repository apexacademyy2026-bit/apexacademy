
This is a large feature. Below is the plan to implement it on top of the existing app (React + Lovable Cloud / Supabase, KaTeX for LaTeX rendering).

## 1. Authentication & Profile changes

- Add a **role selector** (Student / Teacher) on the Auth page used at signup. Stored in a separate `user_roles` table (enum `app_role`: `student`, `teacher`) with a `has_role()` security definer function — never on `profiles`.
- Keep email + password login. Add **Google sign-in** via Lovable Managed OAuth (`lovable.auth.signInWithOAuth("google", ...)`).
- Phone login: enable Supabase phone (SMS) auth so users can sign in with phone number.
- **Profile page (Settings)**: add fields for full name, email (read-only sync from auth), phone, plus a **Change password** form that requires the current password (verify by calling `signInWithPassword` with the current password before `updateUser({ password })`).

## 2. Classes — join code

- Add `join_code` (6-char) to `classes`. Generated by teachers when creating a class, regeneratable.
- Students get a **"Join class"** screen where they enter the code; an RLS-friendly RPC (`join_class_with_code`) validates the code and inserts a row into a `class_members` table linking student → class.
- Teachers see/copy the code from the class detail page. Students they manage are listed via `class_members`.

## 3. Trial Test feature

New section "Trial Test" inside each class. Contains a list of tests created by the teacher.

### 3.1 Teacher authoring

- Test fields: title, duration (minutes), open/closed.
- Three question parts:
  1. **Multiple choice** — 4 options A/B/C/D, exactly one correct.
  2. **True/False** — a statement P with 4 sub-statements (a/b/c/d), each True or False (rendered as the 5-row × 3-column table).
  3. **Short answer** — a numeric answer up to 4 characters from `0-9`, `-`, `,`.
- Statements + options are entered in **LaTeX**. Rendered with **KaTeX** (`react-katex` + `katex` CSS) on both authoring preview and student view.

### 3.2 Student taking the test

- One page shows all 3 parts.
- **Countdown timer** at top from `duration_minutes`; auto-submit on 0.
- Sticky **progress panel** (right side on desktop, collapsible on mobile) with three groups of circular check indicators — filled (primary color) when that question has an answer, empty (white/border) when not.
- MCQ: 4 round radio buttons (A/B/C/D); selected → primary color fill.
- True/False: 3-col table; circular radios in True/False cells, one per row.
- Short answer: 4 adjacent square inputs, only `0-9 - ,` accepted (one char per box, auto-advance focus).
- **Submit** button → confirm dialog → grade.

### 3.3 Grading & results

- Auto-graded client-side then persisted. Score normalized to **/10** (configurable weights, default equal across parts).
- Result view reuses the same layout:
  - Wrong selections shown in **red**; correct answer for each question highlighted; a green ✓ appears before each question the student got fully right.
  - Score shown in a **circular gauge** with the number centered (max 10).
- Students may retake (multiple attempts). All attempts saved.

### 3.4 Teacher view of student progress

- From the class roster, clicking a student opens their attempts list for that class with score, duration, date.
- Aggregated stats per test (avg, best, attempts).

## 4. Database (new migration)

```text
enum app_role: 'student' | 'teacher'

user_roles(id, user_id, role, unique(user_id, role))
has_role(uid, role) security definer

classes:                     + join_code text unique
class_members(id, class_id, student_id, joined_at, unique(class_id, student_id))

tests(id, class_id, teacher_id, title, duration_minutes, is_open, created_at)
test_questions(id, test_id, part 'mcq'|'tf'|'short', position,
                statement_latex, options jsonb, correct jsonb, points numeric)
test_attempts(id, test_id, student_id, started_at, submitted_at,
              answers jsonb, score numeric, max_score numeric)
```

RLS:
- Teachers: full CRUD on their own classes/tests/questions; can read attempts for tests in classes they own.
- Students: read tests/questions of classes they are members of; CRUD only their own attempts.
- `class_members`: student inserts via `join_class_with_code(code)` RPC; teacher of the class can read.

## 5. Frontend additions

- `katex` + `react-katex` deps; small `<Latex/>` wrapper.
- New pages/components:
  - `pages/JoinClass.tsx`
  - `pages/TestList.tsx` (inside ClassDetail tab)
  - `pages/TestEditor.tsx` (teacher)
  - `pages/TestTake.tsx` (student) with timer, progress panel, submit
  - `pages/TestResult.tsx` with circular score gauge
  - `pages/StudentProgress.tsx` (teacher view)

- Settings: phone, change-password section.

## 6. Out of scope for this iteration

- Question images / drawing answers.
- Anti-cheat (tab focus, fullscreen lock).
- Importing tests from PDF/Word — teacher types LaTeX directly.
